# リーダーと画面

[仕様ナレッジ索引](./index.md) · [リポジトリREADME](../../README.md)

<a name="section-3"></a>

## 3. リーダー・対応形式

- iOSの「ファイル」から、UTF-8 Markdown（`.md`、`.markdown`）とDRMなし・リフロー型EPUB 3を開く。同時に読む原稿は一冊。本文は既定で縦書き（`writing-mode: vertical-rl`）、UI・コメントは横書き。iPhoneの縦持ちは一画面一ページ。
- 一行は上から下、行とページは右から左。左端タップ・右スワイプで次へ、右端タップ・左スワイプで前へ。前後ボタンを常設し、Safariの端ジェスチャーと衝突する場合はアプリのスワイプ開始領域を画面内側に限定する。本文の論理順と表示順は一致させる。
- 目次・章名・進捗、読書位置の復元、文字サイズ・行間・明暗テーマを備える。回転や文字設定変更で改ページしても、ページ番号ではなく読んでいた本文位置を復元する。
- EPUBは `spine` の読書順、目次、章扉、見出し、段落、ルビ、対応する同梱画像を対象とする。任意CSS・原稿側のフォントは初版対象外。Markdownの任意の生HTMLは無効。初版の対応範囲は次表を正とし、READMEにも利用者向けに記載する。
- 破損したEPUB、必要リソースの欠落、読み込めないUTF-8、対応容量超過は、理由を明示して拒否し、既存の作業を保持する。入力・展開時に上限を適用する。実機試作で上限と許容時間を決定・記録し、[§9](./verification.md#section-9)のリリース判定に使用する。
- 句読点、括弧、字下げ、ルビ、英数字混じり、章扉・挿絵を検証する。見切れ・重なり・ページ境界での本文欠落や重複を許容しない。

<a name="section-3-1"></a>

### 3.1 初版の対応表

| 対象 | 対応・代替・拒否の方針 |
|---|---|
| Markdown | UTF-8。見出し・段落・改行・リスト・基本的なインライン装飾を表示する。章は見出しから構成する。ルビは `｜親文字《よみ》` の明示形のみ。閉じていない記法や省略形は通常の文字列として表示する。生HTMLは実行・描画せず、画像記法は代替テキストのみ表示する。単体ファイル読み込みのため、別ファイル・外部URLから画像を取得しない。 |
| EPUBの読書順と目次 | `spine` のうち通常読書の対象は `linear="no"` 以外。初版では補助項目を読書・注釈・進捗の対象外とし、対応する目次項目は無効表示または除外する。目次リンクは収録済み本文への内部ジャンプに限定する。ページ送り方向は原稿側設定にかかわらず本アプリの縦書き方向に統一する。 |
| EPUBの章名 | 位置保存用のセクションIDと表示上の章を分ける。目次アンカーと本文見出しから論理位置に対応する章区間を定める。目次の有効な章境界を優先し、なければ本文見出し、さらに無ければ読書順に基づく「セクション n」を用いる。同一ファイル内の章境界も扱う。章またぎの終了章は排他的終端そのものではなく、最後に含む本文の章とする。 |
| 画像 | EPUBに同梱されたPNG・JPEG・静止WebPのみ表示し、縦横比を保って読書面に収める。対応外の画像・装飾は代替文または非対応の表示にする。SVG、動画、埋め込みページ、外部参照は読み込まない。 |
| 対応外要素 | スクリプト、任意CSS、フォント等は無視。表示を許可しない一般のマークアップは、許可された本文として残せる部分だけを表示する。本文の解析や表示に必須のリソースが欠けている場合、破損、固定レイアウト、DRM、上限超過は理由を示して拒否する。 |

## 4. UI・デザインシステム

<a name="section-4-1"></a>

### 4.1 画面構成と操作

| 状態 | モバイル | デスクトップ |
|---|---|---|
| 読書 | 一画面一ページ。章名・進捗・前後操作を最小限にし、目次・一覧は必要時だけ開く。 | 読書面は中央寄せ。本文幅を保てるときだけ「目次／赤入れ」の切替サイドバーを併設。 |
| 範囲指定 | 操作を本文外に置き、Safariの選択ハンドルを覆わない。ページまたぎ中は専用の前後、確定、取消を表示。 | 同じ操作をマウスでも行える。ホバーのみで出る必須操作は作らない。 |
| コメント入力 | 下側の専用パネル。狭いときは可視領域内で全画面に近い表示。保存・取消は可視領域内のフッターに残す。 | 余裕があればサイドパネルに配置し、本文を残す。入力開始のためだけに本文幅を変更しない。 |
| 再割り当て | 一覧から開く。本文選択中はパネルを退避し、確定・取消後は元の一覧項目へ戻る。 | 候補と元の引用をサイドバーに、候補の仮表示を本文に出す。幅が足りなければモバイル構成へ戻す。 |

- 初期値：本文は端末内の明朝系を優先し、`18px`、行間 `1.8`。UIはシステムのサンセリフ系。フォームは`16px`以上、主要タップ領域は`44 × 44 CSS px`を設計目標とする。サイドバーは`64rem`前後を検証の出発点とする。
- ボタンには必要な操作名を付け、前後移動をスワイプ専用にしない。フォーカスは見える輪郭と隙間で示す。選択・入力中は通常のページ送りショートカットを発火させない。

### 4.2 OKLCHカラートークン

テーマは「端末に合わせる／ライト／ダーク」。既定は端末追従とし、明示テーマだけ `data-theme="light"` / `data-theme="dark"` として反映する。設定は保存し、切替で再組版しない。

```css
:root {
  color-scheme: light;
  --canvas: oklch(.955 .012 82);
  --paper: oklch(.982 .011 85);
  --surface: oklch(.995 .003 85);
  --text: oklch(.245 .020 65);
  --muted: oklch(.460 .023 66);
  --divider: oklch(.880 .017 82);
  --control-border: oklch(.580 .022 76);
  --accent: oklch(.430 .095 240);
  --on-accent: oklch(.990 .004 240);
  --danger: oklch(.450 .130 23);
  --question: oklch(.900 .070 88);
  --keep: oklch(.900 .062 160);
  --revise: oklch(.890 .055 22);
  --preview: oklch(.890 .048 242);
  --selection: oklch(.820 .082 242);
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    color-scheme: dark;
    --canvas: oklch(.175 .012 255);
    --paper: oklch(.215 .013 255);
    --surface: oklch(.255 .016 255);
    --text: oklch(.925 .013 85);
    --muted: oklch(.745 .022 255);

    --danger: oklch(.800 .095 23);

  }
}
:root[data-theme="dark"] {
  color-scheme: dark;
  --canvas: oklch(.175 .012 255);
  --paper: oklch(.215 .013 255);
  --surface: oklch(.255 .016 255);
  --text: oklch(.925 .013 85);
  --muted: oklch(.745 .022 255);
  --divider: oklch(.340 .022 255);
  --control-border: oklch(.600 .027 255);
  --accent: oklch(.780 .100 236);

```

| 用途 | トークン |
|---|---|
| 外側／紙面／パネル | `canvas` / `paper` / `surface` |
| 本文と主ラベル／補助情報 | `text` / `muted` |
| 装飾の区切り／識別に必要な操作境界 | `divider` / `control-border` |
| 保存・確定・フォーカス／主要ボタン上の文字／危険操作 | `accent` / `on-accent` / `danger` |
| 疑問／残したい／修正指定 | `question` / `keep` / `revise` |
| 仮表示／選択 | `preview` / `selection` |

数値はsRGB色域内。不透明な指定色のWCAG相対輝度式による計算値は以下のとおり。通常文字4.5:1以上、識別に必要な境界・状態表示3:1以上を基準にし、実際の画面でも確認する。

| 組み合わせ | ライト | ダーク |
|---|---:|---:|
| 本文と紙面 | 15.45:1 | 14.03:1 |
| 主要ボタンの文字と背景 | 7.79:1 | 9.18:1 |
| 本文と3種の注釈背景のうち最低 | 11.47:1 | 8.37:1 |
| 入力欄の境界とパネル | 4.23:1 | 4.00:1 |

本文はハイライト上でも原則として文字色を変えない。仮表示の塗りと紙面の差は約1.31:1（ライト）／1.76:1（ダーク）のため、仮範囲を塗りだけで示さない。仮範囲には隣接色と3:1以上の輪郭等を添え、両テーマで範囲の端を確認できること。仮表示・ネイティブ選択・確定注釈を重ねて濁らせず、確定注釈同士の描画優先順位を固定する。種別は一覧・詳細に文字で出し、色だけに依存しない。読書時には確定ハイライトだけを隠せるようにし、操作中の仮表示には影響させない。

### 4.3 iPhone Safariのズーム・横ずれ・キーボード

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

1. `input`・`textarea`・`select` は `16px` 以上。`user-scalable=no` や `maximum-scale=1` を使わず、利用者のピンチズームを残す。連打するページ送りボタンには `touch-action: manipulation` を限定して使い、本文全体には掛けない。
2. `100dvh` は通常時のアプリ枠に使えるが、キーボード回避はそれだけに任せない。`visualViewport` の `resize`・`scroll` と高さ・`offsetTop` を用い、入力パネルだけを可視領域に収める。セーフエリアとキーボード余白を二重に加算しない。回転やユーザーの拡大をキーボード挙動と混同しない。
3. 引用・範囲・読書再開位置をフォーカス前に確保する。自動フォーカスで安定しない場合は入力欄を直接タップして開始できること。引用の詳細はパネル内部でスクロールし、保存・キャンセルをキーボードや予測変換欄の裏に隠さない。日本語変換の確定キーで誤保存しない。
4. 横書きUIのフレックス・グリッド子要素に `min-width: 0` を用い、長いファイル名・URL・引用は `overflow-wrap: anywhere` で折り返す。全幅に `100vw` を多用せず、画像は枠に収める。縦書きページ送りの横移動はリーダー内部に閉じ込める。文書全体の `overflow-x: hidden` で本文の欠落やはみ出しを隠さない。
