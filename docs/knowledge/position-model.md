<a name="section-6"></a>

## 6. 位置モデル・復元・再割り当て

<a name="section-6-1"></a>

### 6.1 位置モデルと描画

- 原稿版IDは元ファイルのSHA-256。JSON構造の版 `schemaVersion` と本文抽出・位置計算の版 `textModelVersion` を分ける。
- セクションIDは表示上の章名でなく読書順の出現単位。EPUBは `spine` の出現単位、Markdownは同名見出しも区別する。範囲は `start`・`end` それぞれにセクションIDと、セクション本文内の0始まりのUTF-16コード単位の位置（JavaScriptの文字列やDOMのオフセットと同じ単位）を持ち、終了位置は排他的とする。論理本文とDOMの間のオフセット変換を持つ。ページ番号やDOMノード番号は、範囲・読書位置とも永続化しない。
- 論理本文はルビの親文字だけを含み、読み（`rt`）・ルビ括弧（`rp`）・画像の代替文字列・UI文言・組版上の折り返し・縦中横などの表示処理を数えない。各セクションの本文を独立した文字列とし、段落・明示改行はLFで表す。セクションを連結して引用・照合するときは境界ごとにLFを1つ挿入する。このLFはどちらのセクションのオフセットにも含めない。前セクションの末尾と次セクションの先頭は異なる位置で、後者を排他的終端に指定した範囲は境界LFを含む。原稿上の入れ子や書式だけで区切りが重複しないよう、本文を最小の表示ブロック単位に分け、空ブロックは除外し、本文を持つ隣接ブロック間にLFを1つ入れる。明示改行は連続していてもそれぞれLFとする。通常の本文中ではASCII空白とタブの連続を半角空白1つにまとめ、表示ブロックおよび明示改行で区切った各行の両端から除く。全角空白はそのまま残す。Markdownの構文上だけの単一改行は半角空白として扱う。EPUBの段落内で、マークアップ上の整形のためだけの改行も同様とする。抽出結果を正解例とともに `textModelVersion` で管理する。
- 初版は原稿の文字列にUnicode正規化をかけない。改行コードはLFに統一し、範囲の始端・終端は書記素（見かけ上の一文字。`Intl.Segmenter` で判定）の境界にそろえ、サロゲートペアや結合文字の途中で分割しない。位置・引用・文脈・並び順は同じ抽出モデルを使う。文脈は前後それぞれ最大32書記素とし、本文端では取得できる分だけ保存する。
- 読書位置は原則として読書順でページの先頭に現れる本文位置。画像だけのページには、再組版後も同じ画像の出現箇所を探せるようセクションIDと画像の論理出現順を補助アンカーとして保存できる。画像を特定できない場合は、検証できた近接の本文位置へ、本文位置も復元できなければ原稿の先頭へ戻し、理由を表示する。
- 一件につきID・種別・コメント・原稿版ID・範囲・引用・引用の直前直後の本文を保持する。ハイライトは選択色とは分け、表示部分の論理範囲からDOMの範囲を再生成する。CSS Custom Highlight APIは実装候補。
- 同じ原稿版と確認してから位置・引用・文脈を検証する。同一本文モデルでは、保存範囲の両端が有効で、範囲全体の引用と前後文が一致すればその位置を採用する。同じ引用が別にもあることだけを理由に未確定にはしない。本文モデルが異なる、または保存範囲の検証が通らないときは旧オフセットを採用しない。元セクションまたは対応を確認できた元の連続セクション区間で引用・前後文を照合し、範囲全体が一致する箇所を一意に特定できた場合だけ復元する。それ以外は「位置未確定」とし、推測で貼ったり片端だけ描いたりしない。すでに位置未確定として保存された項目は復元しても未確定のままとする。

<a name="section-6-2"></a>

### 6.2 一覧から呼び出す再割り当て

1. 一覧の「位置未確定」から「位置を指定」を開く。元の引用・コメント・記録済みの章を表示し、通常の読書中には割り込まない。
2. 「候補から選ぶ」では、同一原稿版の完全一致候補を示す。元のセクション付近を優先表示し、章名と前後文で区別できるようにする。候補を押すと本文で仮表示するが、一件だけでも自動確定しない。
3. 「本文から選び直す」は候補がないときにも使える。目次・前後移動、長押し・ページまたぎの操作を再利用する。元の引用と新しい引用を見比べ「この位置に割り当て」で確定する。異なる引用はその旨を示し、同一版内での明示確定を許可する。
4. 確定時はID・種別・コメントを保ち、範囲・現在の引用・文脈を更新する。初回の引用はJSONに別項目で保持し、AI提出用Markdownには確定後の現在の引用を使用する。取消時は保存値を変更しない。どちらも元の一覧項目へ戻し、通常の読書再開位置は書き換えない。異なる原稿版への再割り当ては禁止する。

<a name="section-6-3"></a>

### 6.3 位置モデルの正解例

以下の `\n` は1文字のLF、`\u0301` は結合アクセントを表す。位置はUTF-16コード単位。試験素材では実文字を用いる。

| 入力・状況 | 期待結果 |
|---|---|
| セクションAが `甲乙`、Bが `丙丁`。範囲 `(A, 1)` から `(B, 1)` | 引用は `乙\n丙`。終端を `(B, 0)` にすると `乙\n`。組版やページ数を変えても同じ。 |
| `｜火星《かせい》へ`、範囲 `(A, 0)` から `(A, 2)` | 引用は `火星`。読みは位置・引用に含めない。EPUBの `<ruby>火星<rp>（</rp><rt>かせい</rt><rp>）</rp></ruby>へ` も同じ論理本文になる。 |
| `A` に `\u0301` が結合し、その後に `🪐` | `A` と結合記号の間、絵文字のサロゲートペアの間は選択端にできない。先頭の見かけ上の一文字を選ぶ範囲は `[0, 2)`、絵文字は `[2, 4)`。 |
| Markdownで `甲` と `乙` の段落の間に空行が複数ある | 空行は段落の区切りであり、空段落として追加しない。論理本文は `甲\n乙`。EPUBの空の段落要素は本文位置を消費しない。 |
| EPUBの挿絵だけのページ | 画像は本文に数えないが、読書再開用の画像アンカーで再組版後も当該画像を含むページへ戻る。 |
